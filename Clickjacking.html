Clickjacking: UI Redress Saldırısı

Kullanıcının gördüğü arayüz ile gerçekte tıkladığı öğenin birbirinden ayrılması — şeffaf iframe katmanlarıyla kurbanın kendi yetkisiyle istemeden eylem yaptırılması.

UI Redress Attack iframe Embedding OWASP Kategorisi
01

Mekanizma

Tarayıcıların bir sayfayı başka bir sayfanın içine <iframe> ile gömebilmesine dayanır. Saldırgan hedef siteyi şeffaf bir iframe olarak kendi sahte sayfasının üzerine yerleştirir; kullanıcı gördüğü sahte butona tıkladığını sanır, ama tıklama görünmeyen iframe içindeki gerçek öğeye gider.

Kullanıcı hedef sitede zaten oturum açmışsa, işlem kullanıcının kendi yetkisiyle ve kendi çerezleriyle gerçekleşir — sunucu açısından meşru bir istektir.

Ödülünü Al!
hedef-site.com/islem — gerçek buton (opacity: 0)
görünen katman — altında hizalanmış gerçek iframe
Kavramsal yapı
<style>
  iframe {
    position: absolute;
    opacity: 0;        /* görünmez */
    z-index: 2;        /* sahte içeriğin üstünde */
  }
  .sahte-buton {
    position: absolute;
    z-index: 1;
  }
</style>

<button class="sahte-buton">Ödülünü Al!</button>
<iframe src="https://hedef-site.com/islem"></iframe>

Kritik nokta: iframe'in konumu, hedef sitedeki gerçek butonun tam olarak sahte butonun altına denk gelecek şekilde piksel hassasiyetinde ayarlanır.

03

Saldırı Türleri

01

Klasik Clickjacking

Şeffaf iframe yöntemiyle sahte buton üzerinden gerçek öğeye tıklatma.

02

Likejacking

Kullanıcının farkında olmadan bir sosyal medya sayfasını beğenmesi veya takip etmesi sağlanır.

03

Cursorjacking

İmlecin görünen konumu gerçek konumundan kaydırılır; tıklama başka bir noktaya gider.

04

Cookiejacking

Kullanıcıyı iframe içindeki çerez verisini sürükleyip bırakmaya kandırarak çerez çalma.

05

Filejacking

Kullanıcıyı farkında olmadan dosya sistemine erişim izni vermeye yönlendirme.

06

Drag-and-drop / Strokejacking

Sürükle-bırak veya klavye girdisiyle gizli bir alana veri girdirme.

07

Multi-step Clickjacking

"Sil" → "Onayla" gibi çok adımlı işlemler için art arda gizli katmanlar kullanma.

08

Tapjacking (Mobil)

Android'de yarı şeffaf bir overlay ile dokunmaların başka uygulamaya yönlendirilmesi.

04

Gerçek Dünya Etkileri

  • —Hesap silme veya ayar değiştirme
  • —Para transferi veya ödeme onayı verme
  • —Sosyal medyada paylaşım yapma, birini takip ettirme
  • —Kamera/mikrofon izni verdirme
  • —OAuth uygulama yetkilendirmesi onaylatma
  • —Yönetim panelinde kullanıcı ekleme veya yetki verdirme
05

Savunma Yöntemleri

AX-Frame-Options

Sunucu, sayfasının iframe içinde gösterilip gösterilemeyeceğini HTTP başlığıyla belirtir. Eski ama hâlâ yaygın bir koruma.

HTTP Response Header
X-Frame-Options: DENY          /* hiçbir yerde gömülemez */
X-Frame-Options: SAMEORIGIN    /* yalnızca aynı origin'den */

ALLOW-FROM seçeneği artık modern tarayıcılarda desteklenmiyor.

BCSP frame-ancestors

Modern ve önerilen yöntem. X-Frame-Options'tan daha esnektir — birden fazla güvenilir kaynak belirtilebilir.

HTTP Response Header
Content-Security-Policy: frame-ancestors 'none';
Content-Security-Policy: frame-ancestors 'self';
Content-Security-Policy: frame-ancestors https://guvenilir-site.com;

Destekleyen tarayıcılarda CSP öncelik alır. Eski tarayıcı uyumluluğu için ikisini birlikte göndermek iyi pratiktir.

CSameSite Çerez Özelliği

Cross-site iframe içindeki istekte oturum çerezinin gönderilmesini engeller — kullanıcı oturum açmış görünmez, işlem yetkisiz kalır.

HTTP Response Header
Set-Cookie: session=abc123; SameSite=Lax; Secure; HttpOnly

Modern tarayıcılar çerezlere varsayılan olarak Lax uygular; kritik işlemler için Strict değerlendirilebilir.

DFrame Busting (eski JS yöntemi)

Sayfa bir iframe içinde açılmışsa kendini en üste taşımaya çalışır. Güvenilir değildir — saldırgan iframe'e sandbox özelliği ekleyerek veya onbeforeunload ile yönlendirmeyi engelleyerek atlatabilir.

JavaScript
if (window.top !== window.self) {
  window.top.location = window.self.location;
}

Yalnızca ek önlem olarak düşünülmeli, tek başına yeterli görülmemelidir.

Kritik işlemlerde ek doğrulama yüksek etkiSilme veya para gönderme gibi yıkıcı işlemlerde şifre, 2FA veya CAPTCHA istemek; hassas butonlar için ek onay adımları eklemek.
Tarayıcı tarafı korumalar destekleyiciBazı eklentiler (NoScript ClearClick gibi) gizli çerçeveleri tespit edebilir, ama bunlara güvenmek yerine sunucu tarafında önlem almak gerekir.
06

Test Etme

Kendi uygulamanızın savunmasını kontrol etmek için:

  • 01Sayfanızı başka bir domainden basit bir <iframe src="..."> ile gömmeyi deneyin — gömülemiyorsa koruma çalışıyordur.
  • 02Yanıt başlıklarını curl -I https://siteniz.com ile kontrol edin; X-Frame-Options veya frame-ancestors var mı bakın.
  • 03Tarayıcı geliştirici araçlarında Network sekmesinden başlıkları inceleyin.
  • 04OWASP ZAP veya Burp Suite gibi araçlar bu başlıkların eksikliğini otomatik tespit eder.
