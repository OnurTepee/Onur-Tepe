HTTP Host Başlığı Saldırısı Nedir?

Host başlık saldırısı (OWASP'taki adıyla Host Header Injection), HTTP isteğindeki Host değerinin ya da bu değerin yerine geçen başlıkların saldırgan tarafından değiştirilmesidir. Zafiyet başlığın kendisinde değil, uygulamanın bu değere körü körüne güvenmesindedir. Saldırı sonucu, uygulamanın bu değeri nerede kullandığına bağlıdır.

Host Header Injection Virtual Hosting OWASP
01

Host Başlığının İşlevi

Bir web sunucusu aynı IP adresi üzerinde birden fazla siteyi barındırabilir (sanal host, virtual hosting). Sunucu, gelen isteğin hangi siteye ait olduğunu Host başlığına bakarak anlar:

Örnek istek
GET /samples/snippet.html HTTP/1.1
Host: www.example.com

Bu istek, "www.example.com sitesindeki /samples/snippet.html kaynağını ver" demektir.

Uygulamalar da bu değere ihtiyaç duyabilir. Örneğin e-postadaki şifre sıfırlama linkinde, mutlak URL oluşturmak için kendi alan adını bilmeleri gerekir. Geliştiriciler bunu kolay yoldan, yani gelen isteğin Host başlığından alır. Zafiyet buradan doğar.

02

Host Başlığı Nasıl Manipüle Edilir?

Değeri değiştirmek kolaydır. cURL, telnet veya Burp Suite ile istek elle gönderilebilir. Asıl zorluk, isteğin hedef uygulamaya ulaşmasıdır. Üç yöntem vardır.

1Doğrudan sahte Host göndermek

Host değeri bozuksa veya sunucuda tanımlı değilse çoğu sunucu isteği listedeki ilk sanal hosta yönlendirir. Bu durumda rastgele Host değeri yalnızca o ilk siteye gönderilebilir. Bazı sunucular bilinmeyen Host değerlerini tamamen reddeder ve bu yol kapanır.

2Host override başlıkları

Sunucu veya proxy X-Forwarded-Host gibi başlıkları destekliyorsa, bu başlığın değeri asıl Host değerinin yerine geçer:

İstek
GET /index.php HTTP/1.1
Host: www.example.com
X-Forwarded-Host: www.vulnweb.com

Yönlendirme meşru Host ile yapılır, ama uygulama linkleri X-Forwarded-Host'a göre üretir.

3Çift Host başlığı

Sistemler birden fazla Host başlığını farklı yorumlayabilir:

İstek
GET /index.php HTTP/1.1
Host: www.example.com
Host: www.vulnweb.com

Örneğin ön taraftaki sunucu ilk Host'u, arkadaki uygulama son Host'u kullanırsa tutarsızlık oluşur ve zafiyet doğar.

03

Saldırı Türleri

Uygulamanın güvenilmeyen Host değerini nerede kullandığına göre, aynı zafiyet farklı sonuçlara yol açabilir.

  • 01 Şifre sıfırlama zehirlenmesiSıfırlama linki, güvenilmeyen Host değeriyle üretilip kullanıcıya gönderilir; link saldırganın sunucusuna işaret eder.
  • 02 Web önbellek zehirlenmesiZehirli Host değeri önbelleğe alınan bir yanıta işlenir ve sonraki ziyaretçilere o haliyle sunulur.
  • 03 SQL InjectionHost değeri loglama veya sorgu oluşturma sırasında filtrelenmeden veritabanı katmanına ulaşırsa.
  • 04 OS Command InjectionHost değeri sunucu tarafında bir komuta parametre olarak geçiyorsa.
  • 05 İç sistemlere erişimRouting veya yönlendirme mantığı Host değerine göre çalışıyorsa, normalde dışarıdan erişilemeyen iç uç noktalara ulaşılabilir.
  • 06 SSRF (Server-Side Request Forgery)Uygulama, Host değerine dayanarak kendi sunucusundan başka bir adrese istek yapıyorsa, bu adres saldırgan tarafından yönlendirilebilir.
Not: Zafiyetin kök nedeni her zaman aynıdır: istemciden gelen bir değere (Host veya onun yerine geçen bir başlığa) uygulama mantığında doğrulama yapılmadan güvenilmesi. Savunma tarafında tipik yaklaşım, mutlak URL üretiminde Host başlığı yerine sunucu tarafında sabitlenmiş bir yapılandırma değeri kullanmak ve beklenmeyen Host değerlerini reddetmektir.
